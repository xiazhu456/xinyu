## 1. 背景与目标

### 1.1 市场背景

情感陪伴是 AI 落地的核心场景之一。市面上已有很多 AI 聊天产品，但普遍存在三个问题：

- **回应同质化**：不同用户得到相同的回应，缺乏个性化
- **被动等待**：工具放在那里等用户主动使用，而非在需要时出现
- **缺乏深度**：对话无积累，用户没有"被了解"的成长感

### 1.2 产品定位

心屿是一个 **AI 情感陪伴 + 人格分析工具**，核心理念是"每个人都是独一无二的"。它不是一个通用的聊天机器人，而是一个**越来越懂你的陪伴者**。

关键差异点：

| 维度 | 通用聊天机器人 | 心屿 |
|------|--------------|------|
| 回应方式 | 千篇一律 | 基于人格类型的个性化回应 |
| 主动性 | 用户主动发起 | AI 根据情绪主动推荐工具 |
| 深度 | 聊完即忘 | 积累对话，形成人格画像 |
| 角色 | 问答工具 | 陪伴者 + 成长顾问 |

### 1.3 成功指标（MVP 阶段）

| 指标 | 目标 | 测量方式 |
|------|------|---------|
| 人均对话轮次 | ≥ 6 轮/次 | localStorage 记录 |
| 回访率 | ≥ 40% 用户有 2 次以上对话 | localStorage session 计数 |
| 人格分析触发率 | ≥ 60% 有 2 次对话以上的用户产生分析 | API 调用记录 |
| 情绪识别准确率 | 用户对识别结果无明显排斥 | 产品内无负面反馈机制 |

## 2. 用户画像

### 核心用户：小屿

| 维度 | 描述 |
|------|------|
| 年龄 | 18-30 岁 |
| 特征 | 有表达欲但无处可说，或在现实社交中感到孤独 |
| 场景 | 深夜、情绪低落时、有烦恼但不想打扰朋友 |
| 痛点 | 找不到安全的空间表达真实情绪，怕被评判 |
| 核心需求 | 被倾听、被理解、被看见 |
| 次要需求 | 从对话中获得对自己更深的认知 |

### 使用场景

**场景 A：深夜倾诉**
> 凌晨 1 点，小屿失眠了。她打开心屿，输入"今天和室友吵架了，其实也不是大事，但就是睡不着"。心屿以温暖的方式回应，先共情再分析。聊了 8 轮后，小屿感觉好多了，结束了对话。第二天醒来，她看到报告页记录了这次情绪。

**场景 B：自我探索**
> 小屿已经使用心屿 2 周了。她打开"你的岛屿人格"报告页，看到系统根据 5 次对话分析出的 MBTI 类型（INFJ）和九型人格（4 号）。她发现"情绪模式"的描述很准确，截图发到了朋友圈。

**场景 C：情绪调节**
> 小屿在对话中表现出明显的焦虑。AI 在回复末尾主动推荐了 4-7-8 呼吸法。小屿觉得"它真的懂我现在的状态"，而不是在一个工具箱里自己翻找。

## 4. 功能详情

### F1: 流式对话

**优先级：** P0 | **复杂度：** 中

**触发条件：** 用户输入文本后点击发送或按 Enter

**流程：**

```
1. 用户输入文本
2. 前端显示用户消息气泡
3. 显示"心屿正在思考" typing 指示器
4. 前端 POST /api/chat 发送消息历史
5. 后端转发请求到 DeepSeek API (stream: true)
6. 后端通过 SSE (text/event-stream) 逐块转发 AI 回复
7. 前端逐块渲染，实时更新气泡内容
8. 传输完成后设 state.isProcessing = false
```

**边界条件：**

| 条件 | 处理方式 |
|------|---------|
| 网络中断 | 显示"网络出了点小问题"错误消息 |
| API Key 未配置 | 返回 500，提示配置 API Key |
| DeepSeek API 错误 | 转发 HTTP 错误码，前端显示错误消息 |
| 用户连续快速发送 | state.isProcessing 锁阻止 |
| Shift+Enter | 换行而非发送 |

**数据结构输入：**

```json
{
  "messages": [
    { "role": "user", "content": "今天心情不好" },
    { "role": "assistant", "content": "怎么了？" }
  ]
}
```

**数据结构输出（SSE）：**

```
data: {"content": "听起来"}
data: {"content": "你今天"}
data: {"content": "很疲惫"}
data: [DONE]
```

### F2: 情绪分析

**优先级：** P0 | **复杂度：** 低

**触发条件：** 每次 AI 回复完成后自动触发（消息条数为奇数时）

**流程：**

```
1. 前端 POST /api/analyze-emotion
2. 后端调用 DeepSeek API，附带 ANALYSIS_PROMPT
3. DeepSeek 返回情绪分析 JSON
4. 前端更新情绪栏显示：情绪名称 · 强度/10
5. 该次对话结束（endChat）时，最终情绪存入 localStorage
```

**ANALYSIS_PROMPT 核心指令：** 分析主要情绪、强度(1-10)、情绪标签、关键话题、一句温暖建议。

**返回值：**

```json
{
  "primaryEmotion": "焦虑",
  "emotionIntensity": 7,
  "emotionTags": ["工作压力", "自我怀疑"],
  "keyTopics": ["职业发展"],
  "suggestion": "给自己一个暂停的下午，你不需要一直奔跑"
}
```

**边界条件：**

| 条件 | 处理方式 |
|------|---------|
| API 返回非 JSON | 降级显示"未知"情绪 |
| 网络失败 | 静默失败，不影响对话 |
| 对话过短（< 2 轮） | 不触发分析 |

### F3: 人格分析（MBTI + 九型人格）

**优先级：** P1 | **复杂度：** 高

**触发条件：** 用户切换到"你的岛屿人格"报告页时自动触发（需要 ≥ 2 次对话）

**流程：**

```
1. 检查 localStorage 是否有分析缓存
2. 有缓存 → 直接展示
3. 无缓存 → POST /api/analyze-personality
4. 后端组装 PERSONALITY_PROMPT，附带最近 5 次对话的摘要
5. DeepSeek 返回 MBTI + 九型人格分析 JSON
6. 前端缓存到 localStorage，展示人格卡片
```

**MBTI 维度参考：**

| 维度 | 两端 |
|------|------|
| 注意力方向 | E（外倾）/ I（内倾） |
| 认知方式 | S（实感）/ N（直觉） |
| 决策方式 | T（思考）/ F（情感） |
| 生活态度 | J（判断）/ P（知觉） |

**九型人格参考：** 1 号完美型、2 号助人型、3 号成就型、4 号独特型、5 号理智型、6 号忠诚型、7 号活跃型、8 号领袖型、9 号和平型。

**返回值：**

```json
{
  "mbtiType": "INFJ",
  "mbtiDescription": "安静而深邃的倾听者，善于洞察他人情绪",
  "enneagramType": "4号",
  "enneagramDescription": "独特型，渴望理解自我、表达真实感受",
  "personalityTraits": ["敏感细腻", "有同理心", "追求意义"],
  "emotionalPatterns": "在压力下容易自我怀疑…",
  "strengths": ["深度共情能力", "丰富的内心世界"],
  "growthSuggestions": ["学会区分他人的情绪和自己的情绪"],
  "summary": "你是一个…"
}
```

**边界条件：**

| 条件 | 处理方式 |
|------|---------|
| 对话记录不足 | 提示"再多倾诉几次" |
| API 返回不完整 | 缺失字段不展示对应卡片 |
| AI 不确定类型 | mbtiType 可为 null，不展示 |
| 用户点击"更新分析" | 清除缓存，重新请求 |

**重要限制：**
- 所有人格分析是 **推测性的**，基于对话中自然流露的情绪模式
- 产品中避免使用"诊断""鉴定"等字眼
- 不替代专业心理测评工具

### F4: 情绪可视化

**优先级：** P1 | **复杂度：** 低

**触发条件：** 用户切换到报告页

**展示内容：**

- **情绪概览（柱状图）：** 统计所有历史对话中每种情绪出现的次数
- **情绪时间线：** 最近 10 次对话的时间、情绪、对话开头摘录

**情绪-颜色映射：**

| 情绪 | 颜色 |
|------|------|
| 焦虑 | #E8977E 暖橙 |
| 悲伤 | #7EB8C7 蓝灰 |
| 愤怒 | #D47A5E 砖红 |
| 孤独 | #A8C9A5 草绿 |
| 喜悦 | #F5D4A0 浅黄 |
| 平静 | #B5DDE8 淡蓝 |
| 迷茫 | #C9A8D4 紫色 |
| 恐惧 | #D4A0A0 粉色 |

**边界条件：**

| 条件 | 处理方式 |
|------|---------|
| 无情绪数据 | 显示"暂无足够的情绪数据" |
| 仅有一次对话 | 显示图表，但提示"更多数据会更准确" |

### F5: 对话管理

**优先级：** P1 | **复杂度：** 中

**开始对话：**
- 页面加载后自动显示欢迎消息
- 用户输入第一条消息时自动创建 session（sessionKey = `xinyu_session_` + 时间戳）

**结束对话：**
- 每轮对话结束后显示"完成本次倾诉"按钮
- 点击后：
  1. 获取最终情绪分析
  2. 保存完整 session（含消息、情绪、时间戳）
  3. 随机发送一句温暖结束语
  4. 清空当前消息状态
  5. 显示新一轮的起始消息

**数据持久化：**
- localStorage key: `xinyu_sessions`
- 每次结束对话时保存
- 读取失败时初始化为空数组
- 存储满时静默失败

---

### F6: AI 主动工具推荐

**优先级：** P1 | **复杂度：** 低

**设计原则：** 不在交互流程上做独立的功能入口，而是通过 System Prompt 让 AI 在对话中自然推荐。

**触发规则（定义在 System Prompt 中）：**

| 情绪状态 | 推荐内容 |
|---------|---------|
| 焦虑/紧张/恐慌 | 4-7-8 呼吸法 |
| 愤怒/烦躁/激动 | 5-4-3-2-1 Grounding 练习 |
| 悲伤/低落/疲惫 | 送一句温暖鼓励的话 |
| 情绪平和/开心 | 不推荐任何工具 |

**约束条件：**
- 不要每条回复都推荐，仅在情绪明显波动时推荐
- 推荐的语气要自然温和，不机械
- 在回复末尾另起一行，用温和语气推荐

## 8. API 接口定义

### POST /api/chat

| 项目 | 内容 |
|------|------|
| 功能 | 流式对话（转发 DeepSeek API） |
| Request | `{ messages: [{role, content}] }` |

| 结束标记 | `data: [DONE]` |
| 错误处理 | `data: {"error": "..."}` |

### POST /api/analyze-emotion

| 项目 | 内容 |
|------|------|
| 功能 | 分析当前对话情绪 |
| Request | `{ messages: [{role, content}] }` |
| Response | `{ primaryEmotion, emotionIntensity, emotionTags, keyTopics, suggestion }` |
| 模型参数 | temperature: 0.3, max_tokens: 500 |

### POST /api/analyze-personality

| 项目 | 内容 |
|------|------|
| 功能 | 基于多条对话分析 MBTI + 九型人格 |
| Request | `{ sessions: [{date, emotion, messages}] }` |
| Response | `{ mbtiType, mbtiDescription, enneagramType, enneagramDescription, personalityTraits, emotionalPatterns, strengths, growthSuggestions, summary }` |
| 模型参数 | temperature: 0.3, max_tokens: 800 |

## 9. 验收标准

### v1.0 MVP 发布标准

| 编号 | 标准 | 验证方式 |
|------|------|---------|
| AC1 | 用户输入消息后，AI 能在 2s 内开始流式回复 | 手动测试 |
| AC2 | 消息气泡正确区分用户（💝 右侧）和 AI（🏝️ 左侧） | 视觉检查 |
| AC3 | 对话完成后点击"结束"，对话记录保存在 localStorage | 检查 DevTools Application > Local Storage |
| AC4 | 报告页在有 2 次以上对话后显示人格分析结果 | 手动测试 |
| AC5 | 报告页情绪图表正确显示每种情绪的次数 | 手动测试 |
| AC6 | 情绪栏在每 3 条消息后正确更新 | 手动测试 |
| AC7 | 移动端（≤ 600px）下布局自适应、可正常使用 | 浏览器 DevTools 模拟 |
| AC8 | 页面刷新后历史会话不丢失 | 手动测试 |

### 不通过标准

- 对话过程中出现 API Key 泄漏到前端
- 人格分析使用"诊断""鉴定"等医学用语
- 用户自伤内容下 AI 未提供心理援助热线
- 移动端输入框被键盘遮挡无法使用

## 10. 技术架构概要

```
[浏览器] ──── HTTP/SSE ────> [Node.js Express Server] ──── HTTPS ────> [DeepSeek API]
    │                              │
    │ localStorage                  │ .env (API Key)
    │ (xinyu_sessions,             │
    │  xinyu_analysis)             │
    │                              │
    └── 静态文件 ──────────────────┘
    (public/index.html,
     styles.css, app.js)

部署：Railway（Node.js 环境）
命令：node server.js
端口：process.env.PORT || 3000
```
